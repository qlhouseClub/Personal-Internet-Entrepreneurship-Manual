# 从问题到 MVP

MVP 的“最小”不是页面少，而是用最小投入闭合一次真实价值交付。

## 一句话结构

> 为【具体用户】，在【具体场景】中，用【核心机制】把【旧结果】改善为【可衡量的新结果】。

## 四层范围

1. **结果层**：用户最终得到什么。
2. **旅程层**：完成结果必须经历哪些步骤。
3. **能力层**：每一步需要哪些产品能力。
4. **非目标层**：本轮明确不做什么。

## 最小闭环示例

```text
发现产品 → 理解承诺 → 注册/提交输入 → 获得结果
→ 评价/付费 → 获取支持 → 取消或删除数据
```

不要只设计“成功路径”；退款、失败、删除和人工支持也是产品。

## 范围清单

- [ ] 一个明确入口
- [ ] 一个核心任务
- [ ] 一个可验证结果
- [ ] 一个反馈渠道
- [ ] 一个故障/退款/人工兜底
- [ ] 基本分析事件
- [ ] 最小隐私与安全措施

## 不适合先自动化的事项

- 用户需求仍变化的流程；
- 每次都需要不同判断的交付；
- 高风险合规决策；
- 尚未证明用户愿意使用的复杂功能。

先用人工服务、原型或无代码流程验证，再进入 [[产品架构与技术选型]]。
