# 个人站点商业化迁移路线

## 迁移触发器

- 开始站内下单、支付、会员或付费下载；
- 广告、赞助、佣金或服务接单成为稳定收入；
- 需要商户支付、开票、员工或企业客户合同；
- 网站实际内容已明显超出个人备案描述；
- 需要行业许可、平台功能或多用户交易；
- 个人责任、隐私和售后风险上升。

## 阶段 0：冻结扩张

- [ ] 暂停新增付费功能和广告位
- [ ] 记录现有页面、收入、订单和用户数据
- [ ] 列出业务类型：自营商品、服务、数字内容、订阅、广告或平台
- [ ] 不通过修改文案掩盖真实功能

## 阶段 1：选择经营主体

比较：

- 个体工商户；
- 有限责任公司；
- 合规第三方平台验证；
- 是否确实属于无需登记的个人例外。

使用 [[中国经营主体基础]]、[[年度维护成本模型]]。稳定经营时，不要只因为“注册麻烦”长期依赖个人收款和个人备案。

## 阶段 2：确认许可地图

向属地市场监管、通信管理、接入商及行业主管部门核验：

- 市场主体和经营范围；
- 网站/App 备案变更或重新备案；
- 自营销售是否只需备案；
- 是否属于有偿信息服务；
- 是否为第三方提供交易处理、撮合或平台服务；
- 是否涉及 ICP、EDI 或其他增值电信许可；
- 商品或行业许可。

> 从个人备案迁移为企业备案，不等于自动需要 ICP 许可证；也不等于任何业务都只需备案。以真实业务模型判断。

## 阶段 3：域名与备案迁移

- [ ] 确认域名持有人、实名和主体变更方案
- [ ] 向原接入商确认变更主体是否需注销/重新备案
- [ ] 规划可能的审核期和停站要求
- [ ] 更新网站主办者、备案号和联系信息
- [ ] 变更后复核 CDN、云、证书和域名解析

各省与接入商流程可能不同，先取得书面步骤，不盲目注销。

## 阶段 4：经营基础设施

- [ ] 对公或合适的经营结算账户
- [ ] 微信/支付宝等商户支付
- [ ] 发票、记账、申报和对账
- [ ] 合同签署和印章/电子签
- [ ] 客服、退款和投诉
- [ ] 经营者信息和许可公示

- 中国互联网：[[中国互联网合规]]

## 阶段 6：灰度迁移

1. 测试主体信息和新支付；
2. 测试订单、发票、退款和取消；
3. 迁移政策版本和用户同意；
4. 小范围开放真实交易；
5. 监控支付、投诉、税务和数据问题；
6. 确认旧个人收款和旧页面已停止。

## 完成标准

- 实际经营者、域名、备案、支付和发票一致；
- 用户知道向谁购买、如何退款和投诉；
- 订单、支付、银行、发票和账簿一致；
- 广告、商品和服务都有可追溯证据；
- 所需备案或许可已经取得或有书面确认；
- 个人站点不再承载与备案性质不匹配的功能。
